# Protocol notes (for contributors)

This page documents the byte stream generated by the driver. It is based on
interoperability analysis (EU Directive 2009/24/EC, Art. 6) of captured print
streams and publicly distributed PPD / configuration tables, and verified on a
real SC-P900. Anything marked *(assumed)* has not been isolated individually on
hardware.

All multi-byte values in `REMOTE1` commands are little-endian; inside ESC/P-R
packets the length field is little-endian and the payload fields are
big-endian.

## Job layout

```text
00 00 00                         exit packet mode (both Epson and Gutenprint send this)
ESC 01 "@EJL 1284.4\n@EJL     \n" EJL wake-up
ESC @ ESC @                      reset

ESC ( R 08 00 00 "REMOTE1"       ── job block
   TI 08 00  00 YYYY MM DD hh mm ss   time stamp
   JS 04 00  00 00 00 00              job start
   JH <len>  00×6 "\\<hostname>"      job host
   JU <len>  00×3 "<username>"        job user
   HD <len>  00 05 01 02 07 04 + TLV  job metadata shown on printer LCD
ESC 00 00 00                     leave REMOTE1

ESC ( R 08 00 00 "REMOTE1"       ── page / setup block
   TI …
   DP 02 00  00 00
   SN 01 00  00
   US 03 00  00 00 01
   US 03 00  00 01 00
   US 03 00  00 02 01
   DR 04 00  00 'B' 00 00
   PP 03 00  00 m1 m2                 paper path, see below
ESC 00 00 00

ESC ( R 06 00 00 "ESCPR"         enter ESC/P-R
ESC q <len32> "setq" …           print quality      (9 bytes)
ESC q <len32> "seti" …           image processing   (8 bytes)
ESC m <len32> "setm" …           mechanical setting (7 bytes)
ESC u <len32> "chku" 01 00
ESC j <len32> "setj" …           job / page geometry (22 bytes)
ESC p <len32> "sttp"             start page
ESC p <len32> "setq" …           page quality       (12 bytes)
ESC t <len32> "tsnd" …           LCD preview JPEG   (10-byte hdr + JPEG)
ESC d <len32> "bsn2" …           image band, repeated
ESC p <len32> "endp" 00          end page
ESC j <len32> "endj"             end job
ESC @ ESC ( R … "REMOTE1" LD 00 00 ESC 00 00 00
ESC @ ESC ( R … "REMOTE1" LD 00 00 JE 01 00 00 ESC 00 00 00
```

`REMOTE1` commands are `<2 ASCII chars> <uint16 LE length> <payload>`. Build
them with `make_remote1_cmd()` – a wrong length desynchronises the parser in the
printer and it silently skips everything that follows (see "Lessons learned").

## Paper path (`PP m1 m2`)

From Epson's command specification for the SC-P900:

| Source | m1 | m2 |
|---|---:|---:|
| Rear sheet feeder | 1 | 0 |
| Front, fine art / thick paper | 2 | 2 |
| Front, poster board (straight path) | 2 | 0 |
| Front, glossy without eject roller | 2 | 3 |
| CD/DVD tray | 2 | 1 |
| Roll paper | 3 | 0 |

## ESC/P-R packets

Packet format: `ESC <class char> <uint32 LE payload length> <4 ASCII command> <payload>`.

### `ESC q setq` – print quality (9 bytes)

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | MediaTypeID (firmware media ID, e.g. 0 plain, 52 Photo Paper Glossy) |
| 1 | 1 | PrintQuality (allowed values depend on media, see `resolve_firmware_print_quality`) |
| 2 | 1 | ColorMode (0 color, 3 Advanced B&W) |
| 3–5 | 3 | brightness / contrast / saturation *(assumed)*, always 0 |
| 6 | 1 | ColorPlane = 3 |
| 7 | 2 | PaletteSize = 0 |

### `ESC q seti` – image processing (8 bytes)

`CompressMode (1 = RHV2), StaticAPF, ConvertColorSpace, BarcodeMode,
FaceOrder, StandardFastMode, OverCoat (1 off, 2 Black Enhance Overcoat),
GlossPriority`

### `ESC m setm` – mechanical setting (7 bytes)

`MediaSizeID, BorderlessMode, SkipBlankPage, DocumentType (99), BkPrintMode,
BkInkSaveMode, CrossDirectionMode (unidirectional)` – field names as found in
Epson's driver. MediaSizeID 0 = A4, 99 = custom size.

### `ESC j setj` – geometry (22 bytes, 720 dpi units)

`PaperWidth u32, PaperLength u32, TopMargin i16, LeftMargin i16,
PrintableWidth u32, PrintableLength u32, InResolution u8 (1 = 720 dpi),
PrintDirection u8`

### `ESC p setq` – page quality (12 bytes)

`ColorMode, ColorPlane (3), LUT, Gamma u16 (220 = 2.2), PrintDuty, 6 × 0`.
LUT 4 = no color adjustment (host ICC), 0 = Epson standard, 7 = Advanced B&W.

### `ESC t tsnd` – LCD preview thumbnail

10-byte header (`00 01 00 00 00 00` + `jpeg_len u32 BE`) followed by a
272-pixel-tall (rotated 90° CCW to match the SC-P900's 480 × 272 touchscreen)
4:2:0 baseline JPEG (`SOI + merged DQT + merged DHT + DRI + SOF0 + SOS + EOI`
with 0-based component IDs `0, 1, 2` and no `APP0`/`JFIF` marker).

### `ESC d bsn2` – image band

52-byte header (`lines`, `width u16`, `x u32`, `y u32`, `compression = 1`,
rest 0) followed by the compressed band. Bands are 16 lines (8 for the last
partial band). Compression is Epson's RHV2: per band four planes, delta coding
plus a fixed prefix code and run lengths; see [`docs/rhv2-spec.md`](rhv2-spec.md)
and `src/rhv2.c`. The implementation was verified bit-for-bit against the
official driver.

Blank bands at the end of the page are not sent; with `SkipBlankPage = 1` a
completely white page is not printed at all.

## Lessons learned

**"Paper out in roll paper unit" although the rear feeder is selected.**
Early versions of this driver produced this error. Causes found:

1. `REMOTE1` commands whose length field did not match the payload (`JS` and
   `HD` were one byte short). The printer's parser then read the
   `ESC 00 00 00` terminator as payload and swallowed the following `PP`
   command and the entire ESC/P-R header as one bogus command.
2. After fixing the lengths the error remained. Replacing our first `REMOTE1`
   block with the one from a Windows capture fixed it. The difference: the
   Windows stream starts with three NUL bytes, and it does not send
   `SN 00` / `HD 00 03 03` in the job block. The driver now does the same.
   Which of the two was decisive has not been isolated.

**Large jobs aborted half-way.** The printer only accepts data as fast as it
prints and can stall the TCP stream for longer than a minute (paper feed,
cleaning). Do not use a send timeout after connecting.

## Tools

- `test/parse-escp2` from the Gutenprint source decodes ESC/P2 streams.
- The validation snippet used during development walks the two `REMOTE1`
  blocks and every ESC/P-R packet and fails on the first length mismatch; it is
  worth turning into a unit test.
